# 자체 학습: 활동 맥락 모델

현재 구현은 **사용자가 확인한 최근 활동 → 작업 종류**를 학습하는 85개 파라미터의 다중 클래스 로지스틱 회귀 모델이다. 가중치를 처음부터 경사하강법으로 학습한다. 외부 모델이나 LLM API는 사용하지 않는다. Python 표준 라이브러리만으로 학습과 추론이 가능하다. CPU로 충분하며 GPU/HPC는 이 모델에 필요하지 않다.

이는 프로젝트의 최종 연구 모델이 아니라, 실제 사용자 정답 수집·시간 분리 평가·설명 추적을 연결한 첫 학습 경로다. 화면 의미, 실제 집중도, 작업 진척을 알아내는 모델은 아니다. 기존 `research/`의 CNN 학습 경로와 독립적이며, CNN 실험 결과가 이 모델의 성능 근거가 되지 않는다.

## 데이터 수집

1. `python -m local_agent` 또는 `Start-Planwise.cmd`로 앱 실행.
2. 계획을 만들고 작업 종류를 개발·작성·자료 조사·행정·일반 중에서 지정한다.
3. 개인정보 설정에서 활동 수집을 직접 켠다. 기본은 꺼짐이다.
4. 실제 작업 후 앱으로 돌아와 작업을 선택하고 **최근 앱 범주를 선택 작업에 연결**을 누른다. 확인창에 동의한 경우에만 정답을 저장한다.
5. 최근 관측이 60초 이내여야 하며, 정답 저장은 최소 5분 간격이다. 버튼을 반복해서 눌러 학습 표본을 늘리지 않는다.

저장하는 학습 표본은 날짜·시각, 16개 수치 특징, 사용자가 선택한 작업 종류다. 제목·메모·작업 ID·앱 실행 파일명·화면·URL·키 입력 내용은 학습 표본에 포함하지 않는다. 단, 기존 계획 DB 자체에는 사용자가 입력한 제목과 메모가 있다. 범주 통계와 모델 가중치 역시 개인적인 패턴을 담을 수 있으며 익명 데이터라고 주장하지 않는다.

특징: 현재 앱 범주 one-hot 6개, 최근 5분의 범주별 관측 비율 6개, 입력 없음 비율, 범주 전환 비율, 관측 수/20의 상한 1인 비율, 마지막 관측 경과 시간/60. 비율은 실제 사용 시간의 정확한 측정값이 아니다. 화면을 보며 생각하는 시간은 입력 없음일 수 있다. 제외한 범주는 특징 계산에서도 제외한다. 관측이 없거나 오래되면 추론하지 않는다.

기본 보관일은 7일이며 학습 정답에도 적용된다. 장기 실험을 원하면 먼저 앱의 보관일을 직접 늘린다. 활동 기록 삭제와 전체 초기화는 학습 정답도 삭제한다. **이미 내보낸 모델 파일은 자동 삭제되지 않으므로 직접 삭제해야 한다.** 파일은 로컬에 두며 저장소에 커밋하지 않는다.

## 학습과 실행

저장소 루트에서 실행한다. 앱을 종료한 뒤 학습하는 것을 권장한다.

```powershell
python -m local_agent.train --db local_data/planwise.sqlite3 --output runs/activity-model.json
```

별도 저장 경로를 사용했다면 `--db`에 그 DB 파일을 지정한다. 다른 컴퓨터에서 학습할 때는 동일 명령을 쓸 수 있지만 원본 DB에는 계획과 메모도 있으므로 현재 구현에서는 로컬 학습을 권장한다. 데이터 자동 업로드는 없다.

날짜순 앞 약 80%를 학습, 나머지 미래 날짜를 평가에 사용한다. 경계의 5분은 학습에서 제외한다. 최소 3일, 학습 30개·2종류 이상, 평가 10개가 필요하다. **이는 실행 최소 조건이지 연구에 충분한 표본 수 기준이 아니다.** 부족하면 모델을 만들지 않고 이유를 출력한다. 반복적으로 평가 결과를 보며 설정을 바꾼다면 별도 최종 평가 기간을 다시 확보해야 한다.

모델 JSON에는 가중치, 특징 순서, 학습/평가 날짜, 혼동행렬, 정확도, 5종류 macro-F1, 학습 데이터 최빈 종류 기준선, 판단을 보류하지 않은 비율과 그 구간의 정확도가 저장된다. 평가한 가중치 그대로 내보내며 평가 데이터를 이용한 재학습은 하지 않는다.

앱의 **회고와 근거 탭 → 학습 모델로 최근 맥락 확인**에서 JSON을 선택한다. 최근 활동을 기준으로 작업 종류 후보와 해당 종류의 실행 가능한 계획을 보여준다. 같은 종류의 여러 계획 사이를 구별하지 못한다. 계획 우선순위 규칙은 계속 별도로 작동하며 모델이 계획이나 세션을 자동 변경하지 않는다.

최상위 softmax < 0.6 또는 1·2위 차이 < 0.15이면 판단을 보류한다. 이 수치는 초기 정책값이며 실제 개인 데이터로 보정한 신뢰도 기준이 아니다. 확률 보정은 후속 평가 항목이다.

## 설명 방식

각 종류 점수는 `절편 + Σ(특징값 × 학습 가중치)`이다. 앱은 입력값과 항별 기여를 보여주며, 표시된 기여의 합은 모델 점수와 일치한다. 코드에서는 1위와 2위의 점수 차이에 대한 항별 기여도 반환한다. LLM이 이유를 지어내지 않는다.

이 설명은 모델 계산에 충실한 설명이며, 사용자가 실제로 무엇을 했는지에 대한 증명이나 인과관계 설명은 아니다. softmax도 실제 정확도·집중도 확률로 읽지 않는다. 추론 때 사용한 모델과 설명은 판단 기록에 함께 저장되어 나중에 가중치가 달라져도 당시 계산을 확인할 수 있다.

## 동작 검증과 연구 평가를 구분

```powershell
python -m local_agent.train --smoke --output runs/smoke-activity-model.json
python -m unittest discover -s tests -p "test_local_agent*.py" -v
```

`--smoke`는 쉽게 구분되도록 만든 합성 250개 표본 중 200개로 실제 가중치를 학습하고 50개로 실행 경로를 검사한다. 합성 모델은 `synthetic: true`로 표시하며 앱에서 사용을 거부한다. 이 결과는 실제 사용자 성능이 아니다.

2026-10-14 검증: Windows/Python 3.14에서 학습을 실제 실행했고, UI 검사를 켠 20개 테스트가 통과했다. 실제 사용자 정답으로 학습한 모델이나 일반화 성능은 아직 없다.

연구의 주된 비교는 모델 종류 경쟁보다 다음 조건의 효과를 확인하는 것이다.

- 현재 범주만 사용 / 최근 맥락 추가: 동일한 미래 평가 기간에서 오류가 줄어드는가?
- 전체 관측 / 일부 관측 제거: 30·60·120초 간격과 공백 길이에 따른 오류·보류율이 어떻게 변하는가?
- 공통 모델 / 개인 보정: 참여자 단위 외부 평가와 개인의 미래 날짜 평가를 분리한다. 현재 코드는 단일 사용자 평가만 구현했다.
- 설명 없음 / 실제 기여 설명: 사용자가 잘못된 추정을 더 잘 알아보고 수정하는가?
- 계획만 / 맥락 제안 포함: 완료 기준을 충족한 작업 수, 재개 시간, 알림 부담을 비교한다. 세션 시간을 생산성의 정답으로 취급하지 않는다.

후속 비선형 모델(소형 TCN 등)은 충분한 실제 기록을 모은 뒤 추가한다. 단순히 더 큰 모델로 바꾸는 것이 연구 기여는 아니다. 연속 관측 없이 계획에 도움이 되는지, 잘못된 추정을 사용자와 함께 교정하는지가 핵심이다.
