# 복귀 에이전트 설계·Ollama 연동 확인

날짜: 2026-10-14. 이 결과는 설계와 합성 예제 연동 검사이며, 전체 파이프라인 구현이나 사용자 효과 검증이 아니다.

## 설치와 실행

- 로컬 Ollama 0.40.4 확인.
- 사용자 요청에 따라 `ollama pull qwen3.5:4b` 실행 완료.
- 로컬 모델 ID: `d8b0f5e9760c`, `ollama list` 표시 크기 3.3 GB.
- 추론 중 `ollama ps`: GPU 100%, context 4096, runner llamacpp. 이는 로드 상태이며 GPU 사용률이나 peak VRAM 측정은 아님.
- `python scripts/ollama_return_smoke.py`로 실제 로컬 chat API 호출.
- 입력은 `examples/return-card-request.json`의 합성 예제만 사용. 카메라·스크린샷·사용자 DB 사용 없음.

요청은 `think=false`, `stream=false`, `num_ctx=4096`, `num_predict=384`, JSON Schema 출력이었다. 1회 end-to-end 경과 시간은 **71.013초**, 응답 메타데이터의 입력 토큰은 283, 출력 토큰은 115였다. 첫 로드·프롬프트 처리·생성을 분리 측정하지 않았으므로 일반적인 지연이나 정상 상태 처리량으로 해석할 수 없다.

## 결과: 형식 통과, 의미 오류 발견

출력 필드·근거 ID·허용 행동 ID 검사는 통과했다. `review_log` 행동과 `e1`, `e2` 근거를 선택했고, exit code와 결과 파일이 미확인이라는 점은 유지했다.

그러나 다음 의미 오류가 있었다.

| 원본 입력 | 모델 출력 일부 | 판정 |
|---|---|---|
| "다음 행동은 baseline 결과를 표에 옮기기" | "baseline 결과를 표에 옮기는 행동을 수행함." | 미래의 할 일을 이미 수행한 사실처럼 변경 |
| question은 필요한 확인 질문을 담는 필드 | "실험 로그를 확인하는 것이 좋을 것 같습니다." | 질문보다 제안 문장에 가까움 |

따라서 **복귀 요약의 사실성 검사는 실패**했다. 유효한 근거 ID가 사실적 요약을 보장하지 않는다. 단일 예제이므로 오류율이나 한국어 능력의 일반적 수치를 주장하지 않는다.

원본 합성 응답은 로컬 `runs/ollama-return-smoke.json`에 있으며 Git에 포함하지 않는다. 검증 스크립트는 명시적으로 의미 정확성에 대한 사람 검토가 필요하다고 출력한다.

## 설계에 반영한 결정

1. ‘확인된 상태’, ‘남은 일’, ‘다음 행동’은 구조화 필드에서 코드로 렌더링하고, LLM의 자유 요약으로 덮어쓰지 않는다.
2. Qwen의 문장은 제안으로 표시한다. JSON Schema 검사에 더해 action/evidence allowlist, 상태 전이 제한, context revision 검사 필요.
3. 완료·성공 같은 상태 변경은 사용자 확인 또는 사전에 정의한 검증 이벤트만 허용한다.
4. 화면에는 즉시 수동/템플릿 카드를 표시한다. LLM은 백그라운드에서 제안을 보완하며 지연·취소·실패 시 기본 카드를 유지한다.
5. 신규 파이프라인 릴리스 전 계획/시도/완료 시제 혼동, 누락 근거, 상충 기록, 오래된 맥락, 화면 속 악성 지시 등의 사례를 별도 평가한다.

향후 측정: cold/warm 요청을 분리한 p50/p95 지연, 모델 로드 시간, prompt/generation 시간, 입력 길이별 실패율, 취소 이후 오래된 응답 처리, 한국어 카드의 사실 정확성. 이번에는 1회 실제 연동까지만 수행했다.

## 기타 확인

- 합성 정상 출력의 계약 검사와 허용 목록 밖 action 거부 검사 통과.
- 연동 스크립트 Python 구문 검사 통과.
