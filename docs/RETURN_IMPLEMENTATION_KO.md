# 현재 실행되는 기능과 자체 학습 방법

기본 UI는 이후 CustomTkinter의 한 화면 흐름으로 교체했다. 현재 버튼과 실행 순서는 [새 데스크톱 안내](DESKTOP_GUIDE_KO.md)를 참고한다. 아래 탭 이름은 `--classic`으로 여는 기존 화면 기준이며 학습 절차는 동일하다.

2026-10-14 구현 상태. 이 문서는 설계서와 실제 실행 상태를 구분하는 기준이다.

## 바로 쓰는 흐름

`Start-Planwise.cmd`로 실행한다. `.venv-research`가 있으면 그 환경을 사용하고 없으면 기본 Python으로 실행한다. 메모·계획·복귀 카드는 기본 Python으로도 사용할 수 있다. CNN/GRU와 카메라는 아래 연구 의존성이 필요하다.

1. **메모와 하루 계획**: 자유 메모 → ‘할 일 정리해줘’ → ‘좋아, 시작하자’.
2. **계획과 실행**: 세션 기록. 잠깐 멈출 때 메모와 다음 행동을 저장한다. 완료는 직접 확인한다.
3. **다시 이어가기**: 저장된 중단 지점과 그 뒤 확인된 이벤트를 즉시 표시한다. ‘이어서 시작’은 실제로 세션을 시작한다.
4. **다음 행동 도움받기**: 필요한 때 로컬 Qwen에 제안을 요청한다. 기록 본문은 코드가 표시하고 AI 문장은 제안 영역에만 표시한다.

앱은 작업을 대신 수행하지 않는다. 현재 세션 시간을 기록하고 작업 복귀를 지원한다. 실제 집중·진척·생산성의 자동 측정으로 해석하지 않는다.

## 모듈 상태

| 단계 | 실행 상태 | 필요한 것 |
|---|---|---|
| 자유 메모 파싱 | Granite 4 3B, 실제 호출 확인 | Ollama `granite4:3b` |
| 시간 표현 | `1시간`, `1시간 30분`, `40분`을 코드로 환산 | 모델 없이 작동 |
| 복귀 카드 | 저장·조회·수정·다시 시작 연결 | 사용자 계획·중단 메모 |
| 실행 종료 이벤트 | 명시적으로 선택한 PID를 핸들로 관찰 | Windows, 앱 실행 중 |
| 복귀 문장 제안 | Qwen3.5-4B, 실제 호출 확인 | Ollama `qwen3.5:4b` |
| 카메라 입력 | 사용자가 켠 뒤 1회 촬영, 얼굴 crop | OpenCV, 카메라. 실제 사용자 카메라 검증은 하지 않음 |
| 화면 입력 | 사용자가 고른 창만 1회 캡처 | Pillow 12+, Windows. 합성 테스트 창으로 실제 확인 |
| 화면 문구 읽기 | 선택한 이미지에 로컬 Qwen vision 호출 | 추가 버튼 선택. OCR 같은 보조 읽기이며 검증 안 된 문구로 표시 |
| 카메라/화면 CNN | 별도 모델 학습·불러오기·추론 경로 구현 | 실제 데이터로 학습한 가중치 필요 |
| 시간 맥락 GRU | 개념·누락·경과 시간 입력, 학습·추론 경로 구현 | 실제 시퀀스로 학습한 가중치 필요 |
| 개인 보정 | 사용자가 수정한 상태 빈도로 출력 점수 보정 | 명시적 수정 3개 이상. 실제 확률 보정으로 검증하지 않음 |
| XAI | 원본 기록, 개념 수정, 입력 특징 snapshot, 모델 digest, 근거 ID, 개인 보정 전후 점수 | 인과 설명이나 신경망의 완전한 설명을 주장하지 않음 |

**실제 사용자 데이터로 학습된 세 신경망은 아직 없다.** 앱은 모델 없음 상태에서 예측하지 않으며, 합성 데이터 모델은 불러오기를 거부한다. 미학습 상태에서도 메모 파싱·계획·세션·복귀 카드·Qwen 제안은 작동한다.

## Granite 파싱

```powershell
ollama pull granite4:3b
ollama pull qwen3.5:4b
```

여러 줄 입력도 Granite를 거친다. 각 결과에 원본 줄 번호를 요구하고, 누락된 줄이나 사라진 영문 고유명사는 원문으로 복원한다. 모델이 명시하지 않은 시간을 생성하면 그 줄을 원문으로 돌린다. 입력의 모든 한국어 의미가 완벽히 보존된다는 보장은 없다.

예시 `시험 공부 과목 A, 신호 및 시스템, 과목 C`는 공유 행동을 각 과목에 붙인다. `및`이 들어간 과목명은 분리하지 않는다. `1시간`은 60분이다. `30분 후`, `1~2시간`은 소요 시간으로 단정하지 않는다. 여러 항목에 총 1시간을 준 경우 각 항목에 60분씩 복제하지 않고 한 작업으로 보존한다.

Granite 모델은 [Ollama 공식 granite4:3b](https://ollama.com/library/granite4:3b)를 사용한다. Qwen은 복귀·선택적 화면 읽기 담당으로 분리했다. 원격 모델 자동 대체는 없다.

## 관측·개념 수정·연결

‘관측과 학습’에서 해당 종류를 **이번 실행에서 허용**하고 ‘한 번 확인’을 누른다. 화면은 먼저 허용 창을 선택한다. 전체 화면으로 fallback하지 않는다. 창의 핸들·PID·제목이 바뀌면 다시 선택해야 한다. 시작 시 허용 상태는 꺼짐이다.

관측 상한은 모달리티별 30초 간격, 시간당 12회다. 카메라는 얼굴 영역을 얻지 못하면 판단을 보류하고 원본을 저장하지 않는다. 시각 모델이 있으면 모델 출력을 확인하고, 없으면 사용자가 개념을 직접 지정할 수 있다. 확인된 개념은 맥락 모델 입력에 연결된다.

모델 추정 또는 사용자 개념을 반영하면 현재 맥락을 재계산한다. 최근 모델 추정은 해당 작업의 복귀 카드와 Qwen 입력에 **사실과 별도인 가설**로 연결된다. 예측이 작업 상태를 변경하거나 자동 완료 처리하지 않는다. 현재 관측이 없으면 보류하며, 센서를 끄면 해당 모달리티 입력을 마스킹한다.

화면 문구 읽기는 미리보기의 추가 버튼으로만 실행한다. 픽셀은 로컬 Ollama에 보내고 원본은 기본 저장하지 않는다. 후보 문구는 모델 추정으로 표시·보관하며 잘못 읽을 수 있다. 화면 속 명령은 실행하지 않는다.

현재 화면 인식은 저해상도 CNN의 범주 분류와 선택적 Qwen의 문구 읽기다. 별도의 정밀 OCR 엔진, 작은 UI 요소 위치 검출, 개인별 정밀 시선 좌표 보정은 아직 구현하지 않았다. 카메라 분류는 ‘화면 방향/다른 방향/판별 어려움’이며 실제 집중도는 아니다. 원래 설계의 고급 기능과 혼동하지 않는다.

## 학습 자료 수집

시각 자료는 관측 미리보기에서 올바른 라벨을 선택하고 **별도로 연구 이미지·정답 저장**을 눌렀을 때만 PNG와 JSONL을 저장한다. 저장 위치와 원본 이미지 보관을 한번 더 확인한다. 이 폴더는 앱의 기록 삭제와 별개로 직접 삭제한다.

카메라 라벨: `screen_facing`, `away`, `unobservable`.
화면 라벨: `code`, `document`, `terminal`, `video`, `other`.
맥락 라벨: `direct`, `support`, `waiting`, `interrupted`, `unknown`.

맥락은 ‘현재 맥락과 근거 확인’ 후 사용자가 상태를 지정해 교정한다. 60초 이내 반복 교정은 최근 정답을 수정하며 독립 표본으로 증식시키지 않는다. ‘맥락 학습 기록 내보내기’로 JSONL을 만든다. 실제 모델 예측을 그대로 정답으로 저장하지 않는다.

자동 생성된 participant는 `local-user`다. 여러 참여자의 자료를 합칠 때 실제 참여자를 구별하는 가명 ID로 바꿔야 한다. episode는 실행 세션과 날짜로 구별한다. 원본 자료를 HPC로 자동 전송하지 않는다. 작업 메모 DB 전체를 옮길 필요 없이 명시적으로 내보낸 이미지·특징·라벨만 사용한다.

## 학습 실행

Python 환경에 맞는 PyTorch를 설치한 뒤:

```powershell
python -m pip install -r requirements-research.txt
```

개인 미래 날짜 평가용 split을 만든다. 최소 3개의 시간적으로 분리된 episode와 train/val/test 경계에 10분 초과 여유가 필요하다. 이는 실행 조건이지 연구에 충분한 표본 수가 아니다. 여러 사람 일반화 평가는 `--mode people`로 바꾸고 최소 3개의 participant를 구별한다.

```powershell
python -m research.prepare_return --input data/camera/camera.jsonl --output data/camera-split.jsonl --kind camera --mode future
python -m research.prepare_return --input data/screen/screen.jsonl --output data/screen-split.jsonl --kind screen --mode future
python -m research.prepare_return --input data/context-labels.jsonl --output data/context-split.jsonl --kind context --mode future
```

CPU 실행 예시:

```powershell
python -m research.train_return --kind camera --manifest data/camera-split.jsonl --split-mode future --output runs/camera.pt
python -m research.train_return --kind screen --manifest data/screen-split.jsonl --split-mode future --output runs/screen.pt
python -m research.train_return --kind context --manifest data/context-split.jsonl --split-mode future --output runs/context.pt
```

CUDA가 준비된 HPC/랩 컴퓨터에서는 같은 명령에 `--device cuda`를 추가한다. 현재 작업 환경에서 CUDA 학습은 검증하지 않았다. 세 모델은 서로 다른 라벨과 가중치로 학습한다. 이미지 128×128 CNN, 맥락 24개 특징·최대 16시점·hidden 64 GRU가 첫 구현이다.

학습 epoch는 validation loss로 선택하고 temperature도 validation에서 선택한다. test는 최종 모델의 평가에만 사용한다. manifest checksum·seed·split 유형·클래스별 혼동행렬·macro-F1·최빈 기준선·보류하지 않은 비율을 `.metrics.json`으로 출력한다. 특정 클래스가 train에 없으면 결과에 표시한다.

학습한 `.pt`를 앱에서 각각 불러온다. PyTorch `weights_only=True`로 읽고 종류·클래스·특징 순서·가중치 유한값을 검사한다. 신뢰할 수 없는 거대한 모델 파일까지 안전성을 보장하는 샌드박스는 아니다. 학습 데이터 삭제가 이미 학습한 가중치의 영향을 지우지는 않으므로 재학습 또는 모델 폐기가 필요하다.

## 검증 범위

- UI 포함 로컬 기능 41개, 기존 연구 검사 4개, 신규 모델 검사 2개로 전체 47개 테스트 통과.
- 사용자가 제시한 3줄 메모를 Granite가 5개 작업으로 분리했고 `1시간 → 60분`, 과목명·프로젝트명 보존을 실제 호출로 확인.
- Qwen 실제 복귀 제안이 허용 행동·근거 ID를 사용함을 확인. 자유 문장의 일반적인 사실성을 보장하는 검증은 아님.
- 합성 화면의 `Experiment status: RUNNING / Result: NOT CHECKED`를 Qwen vision으로 읽음. 실제 개인 화면은 사용하지 않음.
- 별도 합성 테스트 창만 캡처하고 재촬영 간격 제한을 확인. 실제 카메라를 켜거나 촬영하지 않음.
- 실제 테스트 프로세스의 종료를 핸들로 관찰해 이벤트만 기록하고 task state는 그대로 유지함을 확인.
- `python -m research.smoke_return`으로 세 신경망의 1 epoch 학습·평가·저장과 합성 모델의 배포 거부를 확인. 무작위 이미지/특징이며 성능 수치는 사용자 상황에 대한 근거가 아님.
- 실제 사용자 정확도, 1~2분 계획 작성, 복귀 시간 개선, 장시간 사용 안정성, 배터리 영향은 아직 검증하지 않음.

## 개인정보와 남은 범위

시각 개념·화면 후보 문구·맥락 학습 정답은 기본 7일 보관 후 삭제 대상이다. 계획·복귀 카드·연결 실행 이벤트는 전체 초기화까지 남는다. 개인정보 설정에서 데이터 종류별 차이를 표시한다. 별도 내보낸 연구 원본·모델은 직접 삭제해야 한다. DB 암호화는 아직 없다.

촬영은 사용자가 요청한 단발 관측이며 자동 상시 촬영은 구현하지 않았다. 사용자 상태를 감시해서 강제 복귀시키거나 프로그램을 종료하지 않는다. 트레이/OS 알림, 자동 캘린더 연동, 여러 단계의 계획 그래프 확장, 정밀 시선 보정은 후속 범위다. 현재 연결한 파이프라인을 실제로 학습·평가한 뒤 필요한 기능을 추가한다.
