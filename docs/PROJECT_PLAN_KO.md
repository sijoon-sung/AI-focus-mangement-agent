# Planwise Local 프로젝트 계획서

작성: 2026-10-14. 대상: 실제 개인 사용이 가능한 Windows 로컬 앱과 대학원 지원용 연구 프로젝트.

## 1. 목적

계획 수행 중 생기는 중단, 대기, 필요한 우회 작업, 예상 시간 차이를 관리한다. 활동 관측은 계획 지원을 위한 입력이며 앱 사용량을 집중력·생산성의 정답으로 간주하지 않는다.

> 제한된 로컬 자원과 최소한의 활동 정보로 계획과 실행을 연결하고, 판단 근거를 사용자가 교정할 수 있게 하면 작업 복귀와 계획 실행을 개선할 수 있는가?

설계 제약:

- 소형 모델이나 LLM이 없어도 기본 기능이 작동한다.
- ActivityWatch와 지속적인 화면·카메라 관측을 전제하지 않는다.
- 판단 단계별 데이터 출처와 규칙을 기록한다.
- 관측 부족은 불확실성으로 다루고 비집중으로 감점하지 않는다.
- 추천과 실행을 구분한다. 사용자 파일·일정·프로세스를 자동 수정하지 않는다.

## 2. 사용 시나리오

오늘의 목표 ‘실험 결과 보고서 작성’을 지표 추출, 결과 해석, 방법론 작성으로 나눈다. 결과 해석은 지표 추출이 먼저 완료되어야 하지만 방법론 작성은 바로 시작할 수 있다.

학습 실행을 기다리는 동안 지표 추출을 대기로 지정하면 방법론 작성을 추천한다. 중단 시 복귀 메모와 다음 행동을 남기고 돌아와 재개한다. 완료는 사용자가 확인한다. 추천 화면은 대기 상태 제외, 선행 조건, 가용 시간 등의 이유를 설명한다.

현재 앱은 대기 확인 타이머를 제공한다. 실제 학습/빌드 완료 이벤트 연결은 후속 개발이다.

## 3. 구현 범위

| 기능 | 이번 MVP | 후속 |
|---|---|---|
| 계획 | 완료 조건·다음 행동·종류·예상 시간·우선순위·단일 선행 작업 | 여러 선행 작업, 날짜·캘린더, 하위 작업 |
| 실행 | 세션·전환·중단 메모·복귀·완료 확인 | 실행 프로세스/IDE 연동 |
| 추천 | 가산 규칙, 대기·선행 작업 필터 | 학습된 EBM/작업 연결 모델 |
| 개인화 | 같은 종류의 완료 세션 시간 중앙값, 확인한 앱 범주 빈도 | 풍부한 맥락·시간 변화 대응 |
| 설명 | 기여·제외 이유·버전·입력 스냅샷 | 학습 모델의 기여와 인식 오류 수정 |
| 관측 | 선택적 Windows 앱 범주·유휴 조회 | 허용한 화면의 간헐적 분석 |
| 보호 | 기본 꺼짐·범주 제외·기간 제한·삭제·집계 내보내기 | DB 암호화, 앱별 세밀한 차단 |
| UI | Tkinter 창·앱 내 대기 알림 | 트레이·OS 토스트·설치 패키지 |

첫 버전에는 학습된 신경망·EBM·로컬 LLM이 포함되지 않는다. 사용 가능한 기반과 연구 비교 기준을 먼저 제공한다. 기존 CNN 코드는 선택적 시각 모듈 실험으로 보존한다.

## 4. 구조와 데이터

```text
사용자 계획 ────────────────────────────────┐
                                            ↓
Windows 수집 → 범주화 → 로컬 기록 → 개인 보정/연결 후보
                                            ↓
완료·선행 조건·현재 세션·가용 시간 → 추천 규칙 → 근거 카드
                                            ↓
                         사용자 수정·세션·피드백 → 기록
```

- Task: 완료 조건, 다음 행동, 예상 시간, 우선순위, 선행 작업, 상태.
- Session: 작업 ID, 시작/종료, 복귀 메모. 집중 시간과 구분한다.
- Observation: 시각, 앱 범주, 5분 이상 유휴 여부. 제목과 경로 원문은 저장하지 않는다.
- Link: 사용자가 확인한 작업–앱 범주 연결 횟수.
- Decision: 시각, 추천 대상, 규칙 버전, 입력·기여·제외 사유, 피드백.

SQLite를 사용한다. 같은 데이터 폴더의 중복 실행은 OS 파일 잠금으로 방지한다. 정상 종료 시 세션을 중단하고, 비정상 종료 후에는 마지막 heartbeat 시각에서 세션을 닫아 종료 후 시간을 작업 시간으로 누적하지 않는다. 절전이나 앱 정지 구간까지 정밀 구분하지는 못한다.

## 5. 판단과 XAI

현재 추천 규칙:

1. 완료·대기·선행 작업 미완료는 후보에서 제외.
2. 우선순위 × 10점.
3. 진행 중 세션 유지 +8점, 중단 작업 복귀 +3점.
4. 예상 잔여 시간이 가용 시간 이내면 +5점, 초과면 -5점.
5. 동점은 예상 잔여 시간, 작업 ID 순.

시간 보정은 같은 종류의 완료 작업에서 1분 이상 세션이 3건 이상 있을 때 적용한다. 사용자 예상 50%와 세션 중앙값 50%를 사용한다. 이미 기록한 세션 시간을 빼고 최소 1분으로 표시한다. 실제 업무량을 관측한 값이 아닌 초기 휴리스틱이며 사용자가 예상 시간을 수정할 수 있다.

범주 연결은 명시적으로 확인한 빈도를 사용한다. 최다 연결이 2건 미만이거나 동률이면 보류한다. 자동 작업 전환은 없다. 같은 브라우저 범주 안의 페이지별 목적은 알 수 없다.

근거 카드의 점수 합은 실제 추천 점수와 일치해야 한다. 데이터 흐름 재현, 모델의 설명, 현실의 원인은 서로 다르다. 앱 전환을 생산성 저하의 원인이라고 단정하지 않는다. 후속 EBM의 기여도도 모델 점수 단위로 기록하며 확률의 단순 가감처럼 보여주지 않는다.

‘맥락이 틀림’ 피드백은 평가 기록이며 규칙의 즉시 재학습은 아니다. 작업 수정과 범주 연결 확인은 실제 저장 정보에 반영된다.

## 6. 개인정보

기본값: 수집 꺼짐, 외부 API/텔레메트리 없음, 카메라/화면 캡처 없음.

수집 시 15초마다 앱 실행 파일을 메모리에서 범주화하고 유휴 플래그를 저장한다. 회의/메신저 범주는 기본 제외한다. 앱 종류는 작업 목적과 같지 않다.

활동·판단·그 피드백은 기본 7일 후 앱 실행 중 정리한다. 계획·메모·세션·범주 연결은 직접 삭제할 때까지 남긴다. 원본 화면을 저장하지 않으므로 화면 인식을 원본부터 재검증하는 것은 불가능하다.

DB는 암호화하지 않는다. OS 계정 권한과 디스크 보호에 의존한다. 동기화 폴더라면 --data-dir로 다른 위치를 지정한다. secure_delete/VACUUM으로 논리 삭제하지만 SSD·백업·동기화 사본의 포렌식 삭제를 보장하지 않는다.

기존 저장소에서 추적된 .env와 chroma.sqlite3는 새 브랜치에서 추적을 해제했다. 로컬 파일과 과거 Git 이력은 유지된다. 과거 .env에 실제 자격 증명이 있었다면 별도 폐기·교체가 필요하다. 추적 해제로 과거 노출이 해소되는 것은 아니다.

## 7. 개발 단계

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| 1. 이번 MVP | 계획·세션·복귀·추천·근거·개인정보 | 상태 전이·데이터·설명 합계 테스트와 UI 실행 |
| 2. 개인 pilot | 1~2주 사용과 수정 기록 | 관리 부담·오류·불필요한 알림 분석 |
| 3. 제품 기능 | 선택한 프로세스 완료 감지, 트레이, 작업 분할 | 권한·완료 정확성·종료 처리 검증 |
| 4. 소형 모델 | 구조화 특징→작업 맥락, EBM 후보 | 시간 분리 평가와 설명 충실성 확인 |
| 5. 시각 모듈 | 제한된 촬영 예산의 화면/사물 개념 추출 | 촬영 없이 얻는 성능 대비 추가 이익 |
| 6. 보고서 | 실험·실측 결과·한계·재현 코드 | 과장 없는 대학원 제출물 |

GPU/HPC는 후속 학습에 사용한다. 배포 시 CPU·메모리·배터리 부담은 실제 노트북에서 측정하며 현시점에서 목표 달성을 주장하지 않는다.

## 8. 평가 계획

아키텍처 순위보다 기능의 기여를 비교한다.

- A: 계획 목록과 수동 세션.
- B: A + 중단/복귀와 대기 관리.
- C: B + 개인 기록 기반 추천과 수정 가능한 설명.

개인 pilot은 사용성·오류 발견 단계이며 일반적 생산성 향상을 입증하지 않는다. 후속 연구는 조건 순서를 균형화하고 과제 난도·일별 차이·계획 관리 시간을 기록한다. 표본 수는 pilot의 분산과 최소 관심 효과로 정한다.

평가 항목:

1. 완료 조건 달성, 작업 품질, 계획 변경 이유.
2. 중단 후 다음 유효 행동까지의 복귀 시간. 세션 로그만으로는 직접 측정할 수 없어 추가 사용자 표시/과제 이벤트가 필요하다.
3. 앱 관리 시간, 불필요한 알림, 기능을 끈 비율.
4. 잘못된 작업 연결과 수정률, 미관측 구간의 보류.
5. 설명과 실제 점수의 일치, 입력 수정 효과, 사용자의 오류 발견 능력.
6. CPU·메모리·배터리·관측 빈도.

개인화는 과거 기록으로 계산하고 미래 날짜에서 평가한다. 인접 시간 창이 학습/시험에 섞이지 않게 한다. 시각 모듈을 추가하면 같은 관측 예산에서 고정 주기와 선택적 관측을 비교한다. 유창한 설명에 대한 신뢰 증가 자체를 성공으로 삼지 않는다.

## 9. 선행연구

- [FlowLight, CHI 2017](https://boyangcs.github.io/CHI17FlowLight.pdf): 개인 기준선과 시간적 완화, 읽기/생각하기의 한계. 본 앱 효과의 직접 근거는 아니다.
- [Concept Bottleneck Models, ICML 2020](https://proceedings.mlr.press/v119/koh20a.html): 개념 기반 설명과 사용자 교정. 후속 시각 개념 설계에 참고.
- [InterpretML EBM](https://interpret.ml/docs/ebm.html): 가산 모델 기여도 설명. 후속 모델 후보.
- [GRU-D](https://arxiv.org/abs/1606.01865): 누락과 경과 시간 처리. 원 검증은 다른 도메인이다.
- [LaMP, ACL 2024](https://aclanthology.org/2024.acl-long.399/): 개인 기록 검색. 원 연구는 언어 과제다.
- [To Trust or to Think, 2021](https://www.iis.seas.harvard.edu/papers/2021/bucinca2021trust.shtml): 설명과 적절한 의존을 구분하는 사용자 평가.
- [SHAP 인과 해석 주의](https://shap.readthedocs.io/en/latest/example_notebooks/overviews/Be%20careful%20when%20interpreting%20predictive%20models%20in%20search%20of%20causal%20insights.html): 특징 기여와 생산성의 원인을 구분.

## 10. 포트폴리오

현재 서술: “계획·선행 조건·세션·사용자 수정과 설명 가능한 추천을 연결한 로컬 데스크톱 MVP를 구현했다. ActivityWatch와 외부 LLM 없이 동작하며 개인정보 최소 수집과 판단 기록을 설계하고 기능 테스트를 수행했다.”

실험 전에는 생산성 향상, 집중력 측정, 개인화 AI 성능 개선을 성과로 쓰지 않는다. 후속으로 실제 사용자 효과와 실패 사례를 추가한다.
