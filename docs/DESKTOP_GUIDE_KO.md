# 한 화면에서 계획하고 다시 시작하기

기존 여섯 탭 UI는 시작 후의 상태 변화와 복귀 경로를 찾기 어려웠다. 새 기본 UI는 외부 라이브러리 [CustomTkinter](https://customtkinter.tomschimansky.com/documentation/) 5.2.2로 다시 만들었다. 기본 데이터 폴더와 SQLite는 그대로 사용한다. 새 UI를 열어도 기존 메모·작업·세션은 초기화하지 않는다.

## 실제 사용하는 순서

1. 왼쪽 메모에 할 일을 적고 **할 일 정리하기**를 누른다. Granite 4 3B가 처리 중이면 경과 초가 보인다. 실패하면 실패 안내가 보이고, 같은 버튼으로 재시도하거나 **목록 수정**에서 직접 정리할 수 있다. 실패를 성공한 AI 파싱으로 표시하지 않는다.
2. 목록을 확인하고 **이 계획으로 시작하기**를 누른다. 시간 안에 들어오는 첫 작업의 실제 세션을 시작한다. 이미 진행 중인 작업은 유지한다. 시간에 맞는 작업이 없으면 저장만 하고 그 이유를 보여준다.
3. 오른쪽 타이머가 매초 갱신된다. **잠깐 쉬기**를 누르면 실제 세션이 멈추고 버튼이 **이어서 하기**로 바뀐다. 선택적으로 다음에 할 일을 한 줄 적으면 기록과 함께 남는다.
4. 쉬는 동안 Qwen 3.5 4B의 다음 행동 제안을 받을 수 있다. 설정에서 자동 제안을 끌 수 있고 **다음 한 걸음**으로 수동 요청할 수도 있다. 메모·상태가 바뀐 동안 도착한 오래된 제안은 적용하지 않는다.
5. **완료했어요**는 직접 완료로 기록한다. **완료 취소**로 되돌릴 수 있다. **다음 할 일로**를 누르면 다음 가능한 작업을 선택하고, **이 일 시작하기**로 시작한다.

할 일 카드를 클릭하면 오른쪽 작업이 바뀐다. 다른 일을 시작하면 기존 세션을 중단한다. 앱을 닫으면 시간 기록도 멈춘다. 비정상 종료 이후에는 마지막 heartbeat까지만 기록한다. 화면의 누적 시간은 작업 세션 시간이며 집중도나 생산성의 측정값은 아니다.

## 화면과 복귀 도움

**화면 보고 돕기**는 기존의 선택 창 단발 읽기다. **상단 화면·웹캠**에서는 앱 자체의 주기적 관측을 각각 켜고 끌 수 있다. 화면을 켜면 5초 후부터 현재 활성 창의 보이는 픽셀을 60초마다 읽는다. Planwise 자체가 앞에 있거나 캡처 중 창이 바뀌면 해당 캡처를 사용하지 않는다. Planwise를 연 뒤 평소 작업 창으로 전환하면 된다. ‘화면 다시 확인’도 5초 후 실행하므로 전환할 시간이 있다.

현재 화면 → 로컬 Qwen 문구 전사 → 학습된 화면 CNN/목표 이력 GRU → 관측 결과 표시 및 선택 작업의 근거 저장으로 연결한다. `runs/public-models`의 실제 체크포인트가 있으면 처음 관측할 때 자동 로드한다. 다른 모델은 설정에서 연결할 수 있다. 모델 오류는 표시하며 Qwen 읽기 결과와 구분한다. 다음 행동은 **다음 한 걸음**에서 요청한다. 자동 관측 자체가 알림·작업 완료·앱 차단을 실행하지 않는다.

웹캠을 켜면 10초마다 640×480 프레임을 받고 미리보기와 얼굴 검출 수를 표시한다. 매번 프레임을 받은 뒤 장치를 해제한다. 얼굴 미검출은 부재를 뜻하지 않는다. 어두운 영상에는 렌즈/조명 확인 안내를 표시한다. **현재 웹캠 경로는 얼굴 검출까지이며, 공개 데이터 시선 CNN의 실시간 기하 정규화·보정 및 복귀 정책 연결은 아직 미구현이다.** 시선/집중도 정확도가 검증됐다고 표시하지 않는다.

두 관측 모두 기본은 꺼져 있고 재실행 시 자동으로 켜지지 않는다. **모두 끄기**, 관측 창 닫기, 앱 종료, 관측 기록 삭제로 중단한다. 이미 시작한 로컬 추론은 끝날 수 있지만 중단 이후 도착한 결과는 UI/DB에 반영하지 않는다. 화면·웹캠 원본은 파일로 저장하지 않는다. 웹캠 사진은 Ollama에 전달하지 않으며 화면만 로컬 Qwen에 전달한다. 관측 창을 켜 둔 동안 개인 정보가 화면에 보이면 해당 문구도 읽힐 수 있으므로 화면 스위치로 언제든 멈춘다.

명시적으로 두 관측을 켜서 실행하려면 `python -m local_agent --observe`를 사용한다. 이 옵션은 일반 실행에 자동 추가되지 않는다.

원본 이미지는 파일에 저장하지 않는다. 읽은 문구는 검증되지 않은 후보로 로컬 DB에 저장되며 기본 7일 보관한다. 요청한 화면의 과거 기록을 최대 10분 동안 제안의 근거로 사용할 수 있고, 캡처 시각을 함께 남긴다. **근거**에서 문구·캡처 시각·저장한 메모·AI가 인용한 근거 ID를 확인한다. 현재 화면이나 실제 완료 상태로 간주하지 않는다.

## 방치하지 않는 흐름

- 연속 세션 25분에 화면 안내와 소리로 쉬어도 된다고 알려준다. 강제로 중단하지 않는다.
- 설정의 **5분간 입력이 없으면 시간 기록을 멈추고 복귀 안내**를 켜면 입력이 없던 시간을 제외하고 세션을 멈춘다. 돌아오면 복귀 안내를 표시하지만 자동 재시작하지 않는다. 키 내용·앱 제목·화면은 읽지 않는다. 영상 시청·독서도 입력 없음으로 잡힐 수 있어 기본은 꺼짐이다.
- 설정의 **실행 중인 작업의 종료 기다리기**에서 창을 선택하면 해당 프로그램의 프로세스 종료를 확인하고 선택 작업을 대기로 바꾼다. 프로그램 종료 시 안내하며 완료로 바꾸지 않는다. 창이 없는 학습 subprocess나 브라우저 탭 내부 작업 완료까지 감지하는 기능은 아니다. 앱 종료 후에는 다시 연결해야 한다.
- 알림은 앱 내부와 소리다. OS 알림 센터·트레이 상주는 아직 없다.

## 설치와 진단

```powershell
python -m pip install -r requirements-desktop.txt
ollama pull granite4:3b
ollama pull qwen3.5:4b
python -m local_agent
```

설정에서 Ollama 연결과 설치 모델을 확인한다. 모델이 없거나 서버가 응답하지 않으면 설치 명령과 재확인 버튼을 제공한다. AI 없이도 직접 목록 수정, 시작, 중단, 복귀, 완료를 사용할 수 있다. 네트워크 요청 대상은 `127.0.0.1:11434`뿐이다.

자체 CNN/GRU의 이전 연구 도구는 설정에서 별도로 연다. 웹캠은 상단 **화면·웹캠**에서 직접 사용할 수 있다. 웹캠 경로는 OpenCV 4를 사용하며 한글 폴더에서도 얼굴 검출 모델을 메모리로 읽도록 했다. 이전 세부 계획·활동 분석 화면은 `--classic` 옵션으로 사용할 수 있다.

## 검증

새 UI의 실제 버튼과 DB 상태를 검사하는 8개 테스트를 추가했다. 시작→타이머→중단→복귀→완료→다음 작업, 완료 취소, 실패 표시, 오래된 응답 거부, 입력 없음 시간 제외, 종료 후 데이터 유지, 화면 읽기→제안 연결과 기록 삭제 중 응답 차단을 확인한다.

2026-10-14 Windows 환경에서 기존 테스트를 포함한 전체 55개가 통과했다. 실제 Ollama 통합 검증도 정상 종료했으며 Granite 파싱, Qwen 화면 읽기·제안, 세션 전환과 UI 종료까지 확인했다.

```powershell
$env:PLANWISE_UI_TESTS='1'
python -m unittest discover -s tests -v
python -m research.verify_desktop --output runs/desktop-live
```

두 번째 명령은 설치된 실제 Granite/Qwen을 호출한다. 별도 합성 DB와 직접 만든 검증 창만 사용한다. 제공된 3줄 메모를 5개 작업으로 나누고 60분을 보존하며, 실제 타이머 갱신·AI 복귀 제안·합성 창 `RUNNING / NOT CHECKED` 읽기·화면 근거 연결·복귀·완료·다음 작업 시작까지 검사한다. 결과와 UI 스크린샷은 지정한 출력 폴더에 남긴다. 사용자 카메라나 다른 창을 촬영하지 않는다.

이 검증은 실제 환경에서의 버튼 연결과 로컬 모델 호출을 확인한다. 장시간 안정성, 실제 사용자 화면 인식 정확도, 생산성 향상 효과를 입증하는 실험은 아니다.

2026-10-15 사용자 허가 아래 앱 자체 함수로 실제 활성 화면을 로컬 Qwen·화면 CNN·목표 이력 모델에 전달하고, 웹캠 640×480 프레임 수신도 확인했다. 당시 얼굴 검출 수는 0이었다. 이는 센서/추론 연결 검증이며 정답 라벨이 있는 정확도 평가가 아니다. 개인 화면 문구와 진단 결과는 git에서 제외되는 `runs/live-observation-check/`에만 남고 원본 이미지는 저장하지 않았다. 관측 중단 시 늦은 결과 폐기, 창 전환 중 캡처 거부, 카메라 실패 시 해제, 화면 결과의 근거 연결을 자동 테스트로 확인한다.
